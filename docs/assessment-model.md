# Модель измерения: как считается оценка

## Два слоя, которые делают разное

**Балл по критериям** — публичная величина. Считается автоматически, видна
студенту в любой момент, спорить о ней бессмысленно: критерии открыты
заранее, проверка одинакова для всех.

**Приёмка** — решение человека. Булевое: принято или не принято. Оценивает
не наличие артефакта, а понимание: почему сделано так, чем за это
заплатили, где решение ошибётся.

Разделение нужно, потому что эти вещи расходятся. Артефакт бывает на
месте, а понимания за ним нет — и наоборот, работа бывает сделана, но
оформлена не по форме. Первое ловит только разговор, второе — только
машина.

## Как считается балл

**Балл за модуль = (сумма весов закрытых критериев / сумма весов всех
критериев) × баллы модуля × множитель за срок.**

У каждого критерия есть вес от 1 до 3. Вес отражает не трудоёмкость, а то,
насколько без этого артефакта разваливается остальное: работающий
публичный адрес весит 3, ретроспектива — 1.

Веса — знаменатель для расчёта доли, а не баллы. Сумма весов всех ста
четырёх критериев равна 232, но максимум за семестр — 80 баллов, из
которых модуль M4 даёт 20, остальные по 10.

Критерий считается закрытым, когда по нему выставлен полный балл.
Частичного зачёта нет: либо артефакт удовлетворяет описанию, либо нет.

## Виды проверки

| Тип | Что делает | Пример |
|---|---|---|
| `command` | запускает команду и смотрит код возврата | `docker compose up` поднимает систему |
| `files` | ищет артефакт по смыслу, а не по пути | отчёт об ошибках существует |
| `structure` | проверяет структуру репозитория | evals гоняются в CI с порогом |
| `http` | обращается к публичному адресу | прототип отвечает по своему URL |
| `llm` | выносит суждение по тексту работы с опорой на цитаты | требования обновлены явными правками |
| `human` | не проверяется машинно | на приёмке объяснено, что значат цифры |

Путь к файлу в критерии не указывается намеренно: студент сам решает, как
организовать репозиторий, а проверка ищет артефакт по смыслу. Жёсткий путь
превратил бы задачу в заполнение шаблона.

## Штрафы за срок

Дедлайн один для всего потока. Множитель применяется к баллу:

| Опоздание | Множитель |
|---|---|
| в срок | ×1,0 |
| 1 день | ×0,9 |
| до 3 дней | ×0,7 |
| до недели | ×0,5 |
| дальше | ×0,2 |

Две особенности снимают типовые конфликты:

- **Штраф персональный.** Каждый сдаёт артефакты своей роли своим pull
  request — опоздавший портит балл себе, а не команде.
- **Считается дата первого pull request, а не последнего коммита.** Открыл
  работу в срок — дорабатывай сколько нужно. Пустой запрос не спасает:
  если по теме модуля в изменениях ничего нет, дата не засчитывается.

## Приёмка

Проходит очно с командой целиком, занимает от двадцати до сорока минут.
Разговор идёт по вопросам, привязанным к критериям: у каждого есть признак
хорошего ответа, поэтому приёмку может вести не только автор курса.

Финальный вердикт булевый. Итоговая оценка = баллы со штрафом при условии,
что приёмка получена. **Приёмка — допуск, баллы — величина.** Не принято
— оценки нет, сколько бы баллов ни набралось.

Пропущенная приёмка закрывается на консультации до конца семестра.

## Шкала перевода в оценку

Рекомендуемая шкала при 80 баллах максимума за семестр; вуз вправе
заменить её своей:

| Баллы | Доля | Оценка |
|---|---|---|
| 68–80 | ≥ 85 % | отлично |
| 56–67 | ≥ 70 % | хорошо |
| 44–55 | ≥ 55 % | удовлетворительно |
| < 44 | | неудовлетворительно |

Обязательное условие любой положительной оценки — приёмка получена по всем
семи модулям.

## Если студент выбыл из команды

Критерии его роли остаются в модуле. Их может закрыть другой участник —
тогда штраф считается от даты первого pull request по этой роли. Не взял
никто — критерии остаются незакрытыми, и баллы за них не получает никто.
Команда не наказывается сверх этого.

## Правила использования языковых моделей

Модели разрешены на любом этапе: курс о том, как строить с ними продукты,
запрещать их в работе было бы противоречием.

Ограничение одно и проверяется на приёмке: **студент отвечает за всё, что
сдал**. Если он не может объяснить решение, найденное моделью, критерий не
засчитывается независимо от качества артефакта. Формулировка «так
предложила модель» ответом не считается.

Работа студента при автоматической проверке рассматривается как данные, а
не как инструкции: попытка встроить в репозиторий текст, адресованный
проверяющей системе, эскалируется преподавателю.

## Доказательная база

По каждой сдаче сохраняются: содержимое pull request с датами, результат
проверки по каждому критерию с обоснованием, отметки приёмки с вопросами и
ответами, комментарий преподавателя. Апелляция разбирается по этим
записям.
