# Преподавателю: что нужно для запуска

## Минимум

**Аккаунты GitHub у студентов** и организация, где заводятся репозитории
команд. Работа сдаётся pull request, поэтому git — не пожелание, а условие.

**Доступ к языковой модели.** Подойдёт любой OpenAI-совместимый провайдер.
Расходы на семестр невелики: задачи учебные, контексты небольшие.

**Компьютерный класс с интернетом.** Отдельных вычислительных мощностей
модуль не требует: продукты строятся вокруг моделей, доступных по API.

## Что стоит подготовить заранее

**Темы.** Каталог тем открыт на сайте курса. Своя тема команды и задача от
реального заказчика — предпочтительнее каталожной: у них есть человек,
которого можно спросить.

**Расписание приёмок.** Семь встреч по 20–40 минут на каждую команду.
Двадцать пять команд — это около двадцати часов в семестр только на
приёмки, и это надо заложить в нагрузку честно.

**Дедлайны.** Один на поток для каждого модуля. Множители за опоздание
применяются автоматически, спорить о датах не приходится.

## Что делает программное обеспечение

Автоматическая проверка сдач и ведение приёмки обеспечиваются отдельной
платформой, в состав настоящего фонда она не входит. Она берёт на себя:

- проверку критериев по каждой сдаче с обоснованием;
- очередь приёмок и след разговора: какие вопросы задавались, что
  отвечали;
- расчёт баллов со штрафами и ведомость;
- отчёт по потоку: где команды сыплются чаще всего.

**Без платформы модуль тоже проводится**, но проверка ложится на
преподавателя целиком: сто четыре критерия на команду, умноженные на число
команд. Для одной группы это выполнимо, для потока — нет.

## Сколько времени это занимает

| Что | Часов в семестр на поток из 25 команд |
|---|---|
| Лекции | 16 |
| Приёмки | 20–25 |
| Разбор спорных случаев, консультации | 10–15 |

Основная нагрузка приходится на приёмки, и она равномерно распределена по
семестру: по две-три встречи в неделю вместо аврала в декабре.
