# Модуль M2. ПРОЕКТИРОВАНИЕ СИСТЕМЫ

**Сроки:** Недели 3–4  
**Вес модуля:** 29 баллов  
**Форма аттестации:** защита работы на приёмке (разговор с командой)  
**Компетенции КРМ:** LC-3, LLM-3, LLM-5 — индикаторы LLM-3.1, LLM-3.3, LLM-3.4, LLM-5.2, LLM-5.4 ([сопоставление](../docs/competency-map.md))

## Задача модуля

Превратить понимание проблемы в чертежи: проживаемые use cases, C4-архитектура, прошедшая aact, контракты API и evals, написанные до кода.

## О формате контрольно-измерительных материалов

Отдельных файлов `kim-*.md` и `rubric-*.md` в модуле нет: КИМ здесь —
таблица выше, и она же рубрика.

Причина в том, что оценивание бинарное по каждому критерию: артефакт либо
удовлетворяет описанию, либо нет. Уровней «частично» не предусмотрено — их
нельзя проверить автоматически и вокруг них возникает торг. Градация
появляется на другом уровне: из ста четырёх критериев закрывается больше
или меньше.

Второй слой — приёмка. Она булевая и служит допуском: не принято — оценки
за модуль нет, сколько бы критериев ни закрылось. Вопросы к приёмке
приведены выше по ролям.
